# VideoTracker 全功能测试方案

## 一、测试目标与范围

验证从“发现视频、保存进度、继续观看、标记看完”到“跨设备同步、删除记录”的完整流程，重点保证：

- 视频识别准确，不串视频、不串分集、不重复记录。
- 进度和观看状态保存可靠。
- 观看中、已看完的记录均可同步。
- 删除的记录不会被播放心跳或云同步意外恢复。
- 更新扩展、关闭浏览器、断网等情况下，本地数据仍可正确读取。
- 界面反馈真实，失败时不误报成功。

以当前界面为准：记录管理仅有“观看中／已看完”，默认打开“观看中”。

## 二、测试环境与数据

| 项目 | 准备内容 |
|---|---|
| 浏览器 | Windows Chrome、Edge；发布支持 Firefox 时增加 Firefox 专项 |
| 扩展安装方式 | 正式构建包、开发模式分别测试 |
| 设备与账号 | 两台设备或两个独立浏览器配置，测试账号 A、B，以及未登录状态 |
| 视频平台 | 按下方全球区域矩阵逐站测试，覆盖亚洲、美洲、欧洲、中东、非洲、大洋洲及跨区域平台；四个内置适配站点继续执行 P0 完整回归 |
| 播放器类型 | 普通 video、同源／跨域 iframe、Shadow DOM、单页应用、多视频页面 |
| 视频类型 | 普通视频、分P、剧集、短视频、长视频、直播、广告前后切换 |
| 网络状态 | 正常、慢速、断网、请求超时、服务器错误 |
| 记录数量 | 0、1、3、4、19、20、21、1,000、10,000 条 |
| 特殊文本 | 中文、英文、Emoji、超长标题、HTML 字符、同名不同视频 |
| 同步数据 | 观看中、自动看完、手动看完、手动未看完、已删除、旧格式记录 |

涉及删除、重置同步密码、提交反馈的测试，使用隔离配置、测试账号和测试数据。

优先级定义：

- **P0**：核心流程、数据完整性、账号隔离，发布前必须通过。
- **P1**：常用功能及主要异常处理。
- **P2**：体验、极端数据量和次要兼容性。

### 2.2 每个站点的必测项目

所有矩阵站点先检查网页视频入口是否存在，再按实际内容类型执行下列项目。每站在 Chrome、Edge 分别记录结果；现有四个内置适配站点还须覆盖所有 P0 回归用例。

| 检查项 | 执行要求 | 验收依据 |
|---|---|---|
| 网站入口与样本 | 登记实际国家／地区、最终域名、浏览器版本、登录／会员状态；优先选可合法播放的完整样本 | 不能只检查首页、海报或预告片就认定正片兼容 |
| 标题与视频身份 | 读取标题、时长、视频 ID／集数；若支持分集，连续测试至少两集 | 不串片、不串集，地区版和国内版不误合并 |
| 自动与手动保存 | 验证开关、至少一个非零阈值、暂停和手动记录 | 达到条件才新增，保存的时间来自实际播放内容 |
| 持续进度 | 连续播放超过一个保存周期，再暂停、刷新和切换视频 | 数据更新到正确记录，广告不覆盖正片身份或进度 |
| 恢复与重看 | 保存非零位置，关闭后从扩展打开；已看完后重新观看 | 恢复正确位置，重新观看从头开始；平台自带续播不与插件反复争抢 |
| 分类与删除 | 标记／撤销已看完，再删除播放中的记录 | 状态保留原进度；删除后不被心跳恢复 |
| 跨设备同步 | 同步该站点观看中和已看完的样本，在另一设备恢复 | 视频身份、进度和状态正确；删除标记传播 |
| 站点排除 | 排除实际播放归属域名，再分别播放新视频和已有记录 | 不新增自动记录，但已有记录跟踪和手动保存符合约定 |
| 图标与本地化 | 核对官方图标或通用回退，以及本地文字、超长标题 | 图标不存在时不冒用相似品牌；文字不乱码，阿拉伯语等文字不破坏布局 |
| 登录、地区与播放器限制 | 记录登录墙、会员墙、地区限制、DRM、无网页播放或不可寻址播放器 | 说明具体限制及影响；DRM 标记本身不能替代实际兼容性测试 |

点播至少选择一条有明确时长、可暂停和可定位的视频。支持剧集、短视频、嵌入或直播回放的站点，分别增加对应样本；纯直播不按有限时长视频强行保存百分比，相关项目记录为不适用并注明原因。

### 2.3 逐站结果与覆盖率

为每个站点建立独立记录，通用模板如下：

| 地区编号 | 平台／地区版 | 实际播放域名 | 测试地区 | 浏览器及构建 | 样本链接／类型 | 登录／会员条件 | 识别与保存 | 进度与恢复 | 状态／同步／删除 | 图标 | 结论／限制／缺陷编号 |
|---|---|---|---|---|---|---|---|---|---|---|---|

- **通过**：已实际播放并验证该样本所适用的核心流程，附证据。
- **部分通过**：例如可记录但不能恢复，逐项列出通过和失败内容，不能计为完整兼容。
- **失败**：播放条件满足，扩展未达到预期，登记缺陷。
- **阻塞**：缺少地区环境、账号、会员或网络条件，未能进入实际播放；不得计入通过。
- **不适用**：站点或样本没有该能力，例如纯直播没有总时长；必须写明原因。
- **待测**：尚未执行，不得标记为通过或对外宣称兼容。

每个地区分别汇总已测、通过、部分通过、失败、阻塞和待测数量。首页可访问、图标正确、单元测试通过，均不能替代真实站点播放验收。首轮矩阵内每个站点都必须有结论或明确的阻塞记录；新增或合并的平台在下一轮更新矩阵和域名清单。

## 四、发布前必须跑通的端到端流程

### 流程 A：本地观看闭环

全新安装 → 完成功能引导 → 开启自动记录 → 播放达到阈值 → 暂停 → 确认记录 → 关闭视频 → 点击继续观看 → 核对位置 → 标记已看完 → 在已看完分类找到 → 重新观看 → 回到观看中。

验收重点：全过程不重复记录，进度和分类始终一致。

### 流程 B：排除站点与手动保存

关闭站点自动记录 → 播放新视频不新增 → 手动保存 → 继续播放 → 暂停后进度更新 → 移出排除名单 → 新视频恢复自动新增。

验收重点：新增限制与已有记录跟踪互不混淆。

### 流程 C：两设备同步闭环

设备 A 保存观看中及已看完记录 → 同步 → 设备 B 解锁并拉取 → B 修改进度和状态 → 同步回 A → A 删除一条记录 → B 同步。

验收重点：状态保留、合并正确、删除后不复活。

### 流程 D：断网与恢复

已有本地记录 → 断网 → 保存进度、改变状态 → 同步失败 → 恢复网络 → 重试同步 → 另一设备核对。

验收重点：本地操作不依赖云端，失败不丢数据。

### 流程 E：云端密钥重置

两设备完成同步 → A 重置同步密码 → 核对 A 本地记录 → B 用旧密钥同步被拒绝 → B 用新密码解锁 → 再次同步。

验收重点：旧密钥无法覆盖重置后的云端数据。

### 流程 F：版本升级

准备旧版记录、站点规则和设置 → 安装当前构建 → 检查全部数据 → 打开升级前的视频页面 → 保存进度 → 切换已看完 → 同步。

验收重点：界面和后台版本一致，原数据可继续使用。
