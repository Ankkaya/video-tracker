## 发布步骤与待办

1. 在 Chrome Web Store 开发者后台新建或选择正确的扩展，上传上述 ZIP。当前连接的浏览器不允许自动控制商店后台，因此本次没有执行上传或提交。
2. 获取该条目的正式扩展 ID。核对 Supabase Authentication 的重定向允许列表含精确地址 `https://<正式扩展ID>.chromiumapp.org/`。Google OAuth 的回调仍为现有 Supabase `/auth/v1/callback`，不要将其替换为扩展地址。
3. 按 `listing.json` 填写中文和英文详情，上传对应截图、图标及宣传图，填写公开隐私政策链接。
4. 隐私表单按实际行为披露：登录邮箱及账号标识、认证信息、观看网址与记录、页面标题及封面等内容。涉及个人身份信息、身份验证信息、网页浏览记录和网站内容等类别；根据后台定义逐项核对。可选同步加密不代表未处理数据。没有出售数据、广告或分析用途。
5. 在权限说明字段填写 `docs/STORE_LISTING.md` 的对应说明。`commands` 是快捷键声明，不是单独申请的权限。代码随包提供；没有故意加载远程执行代码的功能，提交前仍应以商店扫描结果为准。
6. 使用正式扩展 ID 的版本验证 Google 登录、退出、加密同步及跨设备解锁；本轮仅通过自动测试及预览交互，尚未进行该项正式 ID 验证。Google OAuth 应用已设为正式版，但这不代表扩展已上架。
7. 审核说明写明本地功能无需账号，自动记录默认关闭；提供手动保存、自动记录、恢复、站点控制的测试步骤。若后台要求同步测试账号，通过私密审核字段提供，不要写入公开介绍。
8. 部署本次 `landing/index.html` 和 `landing/en/index.html` 的隐私摘要修正（本轮只修改本地文件），核对公开首页与完整政策一致，然后提交审核。

开发者注册、双重验证、费用或协议若被后台要求，需要账号持有人完成；本轮未能从商店后台确认这些状态。
